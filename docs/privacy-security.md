# Privacy and security choices — Udyam Digital

**Scope.** Local competition prototype with optional cloud AI, using fictional applicants and identifiers. It does not verify a real person's identity or establish legal compliance. No real customer information should be entered.

**Purpose and minimisation.** The advisor initially collects only segment, business type, team size, sites, city tier, budget, term and required services. GSTIN is optional until a product needs it. Contact information is not requested. KYC collects a GST or Udyam registration document, address proof and signatory ID to check registration, address, document age and signatory role. No marketing or unrelated profiling is performed.

**Consent and choice.** A separate notice explains purpose, local processing, retention and withdrawal before document loading/upload. The server blocks OCR and specimen loading without consent. Withdrawal clears documents, verification results and any demo order. Reset starts a fresh session. The interface offers English and Hindi; the privacy notice is translated.

**Processing and disclosure.** Uploaded documents are read by local OCR. GSTIN and Udyam lookups use supplied fictional CSV registries. No external AI or government service receives KYC records. Guided mode makes no external requests. Optional AI chat requires separate consent: advisor messages, business requirements and catalogue context are sent to the explicitly selected provider (Gemini or OpenAI), while KYC documents and registry records remain local. Common typed identifiers are redacted; users must still avoid entering sensitive free text. The API key is stored in an ignored owner-only local file or server environment, never exposed to the browser. OpenAI requests set store:false, which is not a guarantee of zero provider retention. Gemini free-tier content may be used to improve Google products; a separate provider-specific notice explains this before chat consent. The app never automatically falls back to a different provider. The OCR engine and English model must be installed/downloaded before offline use. A cached extraction of the distributed synthetic specimens is included for reproducible demonstrations; it is not a store of user uploads.

**Retention.** Raw uploads use temporary files, removed after OCR completes or fails. Extracted document text is held only in server memory and cleared after successful checkout, KYC-consent withdrawal, reset or session expiry. Advisor history remains until conversation clearing, AI-consent withdrawal, reset or session expiry. Order and profile state expire after 30 minutes of inactivity. Distributed synthetic dataset files and their specimen OCR cache remain part of the project, independently of a visitor's session.

**Controls and limits.** The server binds to localhost. Session cookies are HTTP-only and SameSite=Strict; POST requests require a CSRF token. Uploads have size, resolution and image-format limits; static paths cannot read the dataset or server files. Access logs are suppressed, and displayed extracted identifiers are masked. Quotes and checkout are revalidated server-side. OCR uncertainty fails to review rather than automatically approving a document. Role and fuzzy text checks do not prove document authenticity, identity or authority. HTTPS, authentication, encryption at rest, formal rights/request handling, authorised KYC integrations and audited operational access are required before real deployment.
